# 显示行为说明

中文（默认）| [English](display-behavior.en.md)

> 本项目为**完全原创**作品，与 [JanEickholt/dsh-inline-diff](https://github.com/JanEickholt/dsh-inline-diff) 及任何其他同名/相似插件、仓库没有任何关系，也不是任何项目的衍生或复刻作品，详见 [README 原创声明](../README.md)。

本文解释内联差异卡片与「放大 / 全文对照」弹窗在**数据来源、刷新规则、行号与弹窗层级**上的行为，方便使用时判断“看到的到底是什么”。版本变更历史请看 [CHANGELOG](../CHANGELOG.md)；本文不记录版本号。

## 1. 卡片数据从哪来：执行快照，不是实时读盘

- 每次 `edit` / `write` 执行完成时，工具结果里本身就带有 **`before` / `after` 文件文本**（新建文件时 `before` 为空）。
- 插件 Host 端在工具结果返回时截取 `{ path, before, after, operation }`，按「会话 + 调用 ID」保存为**内存**快照（LRU，最多 240 条；每侧文本上限 4MB，超限的写入不保存快照）。不写磁盘、无网络请求。
- 卡片渲染时向 Host 取一次这份快照（浏览器侧也按调用 ID 缓存，避免重复请求），之后**卡片、放大弹窗、全文对照都用这一份数据**，不会再次读取文件。
- 因此：点击「放大」、切换「全文对照」都只是**换一种布局展示同一份快照**，不会重新读盘、不会重新执行 diff、也不会轮询刷新。

`str_replace_editor` 与历史回放没有这份 Host 快照：卡片改用工具结果中自带的 `meta.diffs` 差异块（Host 已按上下文裁剪），并能读取一次当前文件来补齐行号；这类展示不重新计算整文件对齐，因此「全文对照」不可用。两者在说明文案上有区分：`str_replace_editor` 是「该工具调用不保存执行快照」，只有 `edit` / `write` 快照丢失（应用重启、LRU 淘汰、超出快照上限）才叫「历史回放」。

## 2. 全文对照的刷新规则

- **同一张卡片永远展示它那一次编辑的快照**：`before` = 调用前全文，`after` = 调用后全文。文件之后被别的编辑修改，不会回头改变旧卡片。
- 退出弹窗再重新打开同一张卡片，看到的仍是**同一份快照**（浏览器按调用 ID 缓存；Host 也按调用 ID 保留同一份），不会变成文件的最新版本。
- 想查看文件的最新内容，请打开**最新那次编辑生成的卡片**再点「全文对照」；每张卡片对应一个独立的编辑动作。
- 插件没有“旧卡片实时查看当前文件”的功能，这是有意设计：卡片代表一次变更事件，而不是文件当前状态。
- 正在执行、尚未返回结果的调用只显示**参数预览**：`edit` 类预览基于 `old_string` / `new_string` 片段，不显示精确行号；`write` 预览基于写入内容，行号从 1 起算。结果返回后再替换为执行快照。

## 3. 历史回放（降级）与那一次文件读取

- 当 Host 快照不存在时（DSH 应用重启、快照被 LRU 淘汰后重放旧会话、或写入超过快照上限），卡片会退化为**历史回放**模式：
  - 只展示工具元数据中的修改块与（尽量恢复的）行号，无法还原修改前全文；
  - 放大弹窗顶部显示一条**固定说明横幅**，「全文对照」页签置灰；
  - 此时卡片首次渲染会额外读取一次**当前文件**（读缓存 15 秒；前提是工具结果带有文件路径），且只用于**补齐行号**，不会因此获得全文对照能力。
- 行号定位也基于当前文件：如果文件后来又被改动导致无法唯一定位，行号会显示「行号待定」，弹窗内同样有说明。删除型修改块在文件里没有足够的上下文锚点时也可能无法定位。

## 4. 行号栏：旧 / 新

- **内联卡片里，每个有精确行号的修改点会在横条下方显示一行与行号列严格对齐的「旧 / 新」图例**（旧为红系、新为绿系）；行号待定的修改点不显示图例。放大弹窗则用顶部的「修改前 / 修改后」栏区分两栏。
- 图例按修改点实际存在的行号显示：普通修改点显示「旧 新」两列；**新建文件**（只有新行号）只显示「新」，**纯删除**（只有旧行号）只显示「旧」，不会给不存在的行号列安上标签。
- 删除行的旧行号用红系轻微染色并加粗；增加行的新行号用绿系染色并加粗；未改动的上下文行两列行号保持灰色。
- 行号可能错位（例如旧 L454 对应新 L455），横条会给出“旧 Lx–Ly → 新 Lm–Ln”的范围；配合图例可快速判断哪一列属于修改前、哪一列属于修改后。
- 折叠的内联卡片内容区最高 360px，差异区合计最多展示 42 行（按修改点顺序分配行预算）；超出的行以提示文字说明，并可点「放大」在弹窗中查看全部。

## 5. 放大弹窗的层级与滚动

自上而下：

1. 标题行：文件图标、文件名、语言徽章、操作与 `+ / −` 统计、旧/新文件行数、「变更块 / 全文对照」切换、关闭按钮；
2. 说明横幅（历史回放、行号待定、全文对照不可用等，**仅在需要时出现**）；
3. 「修改前 / 修改后」栏；
4. 滚动区：修改点横条吸顶，下面是对比内容；
5. 底部状态栏（对照来源、旧/新文件行数、`Esc · 关闭` 提示）。

说明横幅与「修改前 / 修改后」栏都是**固定表头**，不随内容滚动；右侧滚动条只属于滚动区，从它们下方开始，不会覆盖横幅或标题。修改点横条吸顶在滚动区顶部，只会盖住对比内容，不会盖到标题、横幅或栏上。点击遮罩或按 `Esc` 关闭弹窗。

弹窗尺寸为 `min(1440px, 96vw) × min(900px, 90vh)`，通过 React Portal 挂到 `document.body`，层级高于宿主外壳与第三方浮动层；窄屏（≤860px）时左右两栏改为上下堆叠。

## 6. 设置弹窗

- 弹窗表面使用主题的分层表面色（官方深色外观下为 `#2c2c2e` 深灰，浅色外观下为浅色），标题、说明与控件保持可读的对比度；不会因为误用遮罩色（`bg-overlay` 在官方深色主题里是中间灰）而出现整块发白的灰面板。
- 「内联差异 · 显示样式」的标题、说明与关闭按钮组成**固定横幅**，设置内容在下方独立滚动，滚动条不会覆盖横幅，也不会随内容滚走。
- 弹窗自身裁剪圆角，滚动内容与滚动条都限制在弹窗内，滚到最顶/最底不会溢出；滚动条与右边缘保留内边距，不贴（也不越过）弹窗边框。窄屏（≤720px）时每项设置的控件改为在说明下方竖排。
- 开启「其它工具调用 → 展开风格」时，如果「过程折叠」仍为 DSH 原生，插件会自动把它切到「不折叠」，避免已完成的工具行被 DSH 折叠组遮住；「恢复默认」会一并恢复本地选项与 DSH 对话记录偏好，若「其它工具调用」因此变化，页面会自动刷新一次以应用变化。
- 弹窗与设置页使用同一个面板；侧边栏底部「差异样式」打开弹窗，DSH 设置页「内联差异」内嵌同一套内容。

## 7. 展开风格卡片的 IN / OUT

- 命令执行与工具调用卡片内部是 **IN / OUT 两段**，各自拥有独立滚动区域（IN 限高 180px，OUT 限高 260px）；滚动条贴卡片右边缘（与文件修改卡片一致），文字内边距由滚动容器自己保留，不会被滚动条压住。
- 左侧色条按段显示状态，为每段约 2.5px 的左描边：输入准备/等待输出 = 主题色（脉动），输入侧完成 = 绿，输入侧失败 = 红；输出执行中 = 主题色（脉动，含「执行中…」占位），输出成功 = 绿，执行失败/非零退出 = 红，用户中止 = 警告色；输入侧失败时 OUT 段标为「跳过」并保持中性色。
- 失败归因：`INVALID_ARGS` / `UNKNOWN_TOOL` / `ABORTED_BEFORE_DISPATCH` 归输入侧，其余执行期错误与非零退出码、信号中止归输出侧；缺少错误码时，若原始参数不是合法 JSON 对象，也归输入侧。输入侧失败时 IN 代码为红字，输出侧失败时 OUT 代码为红字；正常文字使用跟随内部配色与明暗外观的默认前景色。失败文本只出现在对应的 IN / OUT 段内，卡片在 IO 面板处结束，不会在面板下方再追加一段重复错误行或额外外壳。
- 状态点只在**输入与输出都成功**时显示绿色；任一侧失败为红色；用户中止为警告色；执行/准备中为主题色并脉动。
- 两段之间只保留一根细分隔线；最后一段的左描边沿卡片底部圆角收起，与卡片圆角对齐。

## 8. 大文件与渲染性能

- 全文对照最多渲染 4000 行；超过时截断并显示说明。任一侧超过 4000 行、LCS 对齐预算（单侧 4000 行 / 250 万格）超限时，自动降级为修改块模式（弹窗有说明横幅）；若连工具元数据差异块也没有，则使用前后缀 + 替换块的粗对齐，颜色与行号仍准确，但关闭移动识别。
- **物化预算（1.3.0 新增）**：浏览器在把文本拆成逐行对象之前先测量预算；任一侧超过 20 万行或单行超过 100 万字符时不再物化逐行内容，只保留准确行数与增删统计并显示「文件过大」降级提示。这是为避免 4MB 级输入生成数百万行对象、导致页面冻结或内存溢出的最后一道防线。
- 折叠的内联卡片最多渲染 42 行（跨修改点共用行预算，超出部分给出提示）；卡片内容区最高 360px，内部滚动。
- 语法高亮只对可用数据分词一次：整侧不超过 200k 字符 / 4000 行时按全文分词并逐行索引，否则放弃高亮；历史回放按修改块局部高亮。单行超过 2000 字符不 token 化，回退默认前景色。
- 行内 token 级 diff 有独立预算：单行 4000 字符、16 万格，整段累计 200 万格，超出则该行只显示整行级颜色。
- 行数较多时，快速滚动全文对照可能出现**短暂的闪一下/白闪**：这是浏览器对大块带语法高亮 DOM 进行滚动栅格化、并叠加弹窗背景模糊合成时的渲染表现，属于性能现象；数据是静态快照，不会因闪烁改变，内容与行号始终正确。
- 目前未做懒渲染优化；若后续需要，可改为只渲染视口附近的行、或对超大文件降低高亮密度。Read 范围观察器只响应 Read 行相关 DOM 变更，并延迟到首帧后扫描，避免长会话与启动动画期间产生额外的整页查询。

## 9. 隐私

- 默认无网络请求、无遥测；快照仅在 Host 内存中短暂保留，不落盘；设置只写入浏览器 `localStorage`，不含文件内容。
- 例外：用户主动点击设置页「检查更新 / 安装」时，Host 会访问 npm registry 读取版本列表、并调用本机 `dsh` CLI 安装插件；请求只包含包名/版本号，不发送会话内容、文件内容、密钥或设备信息，也不会自动后台联网。

## 10. 动效

动效只服务于「从无到有」的瞬间，不做装饰性循环动画：

- **运行中卡片入场**：命令执行/工具调用卡片在挂载时若仍处于「准备中 / 运行中」，播放一次 200ms 的淡入 + 4px 上浮；历史回放、已结算的卡片和几毫秒就完成的调用直接显示终态，不加动画。
- **输出出现**：OUT 从「执行中…」占位切换为真实输出时，OUT 段播放一次 160ms 淡入 + 2px 上浮；状态没有变化的重渲染不会重复播放。
- **弹窗打开**：设置弹窗与放大弹窗打开时，遮罩 140ms 淡化、对话框 200ms 淡入 + 0.985→1 缩放 + 6px 上浮。
- **性能与可访问性**：只用 opacity/transform（不触发布局重排）；缓动为强 ease-out 阻尼曲线，没有回弹、过冲或夸张位移；系统启用「减少动效」（`prefers-reduced-motion: reduce`）时全部关闭。
- 动画只作用于本插件自己的 DOM，不影响 DSH 原生行、第三方主题或启动动画插件的动画。

## 11. 版本与更新面板

- 设置面板底部「版本与更新」提供：当前版本、当前 DSH 版本、「检查更新」按钮、npm 全部版本列表（最新 / 当前 / 已废弃 / 不可安装、发布时间）与「更新到 / 回退到 / 重新安装」按钮。
- 「检查更新」由 Host 代理请求 npm registry（60 秒缓存、12 秒超时），仅在用户点击时访问外网，结果只包含包名与版本号。
- 「安装」仅在 Web profile 可用：Host 复用现有同源/loopback 准入，校验目标版本必须存在于 registry 列表且可安装，然后串行调用本机官方 CLI（`dsh plugin --profile <name> add @him666233/dsh-inline-diff@<版本>`；argv 直传、不经 shell、240 秒超时并杀进程树），成功后再复核 `node_modules` 中实际安装版本。
- 安装完成后**必须重启 DSH**（Web 重启 `dsh web`，桌面重启应用）才会加载新版本；只刷新页面不够。
- 桌面端 v1 受官方「先完全退出桌面端再修改 desktop profile」约束，不提供运行中一键安装，改为显示版本列表与可复制命令。
- 失败路径：版本不存在/不可安装/非法格式在进入安装前被拒绝；CLI 失败时官方安装器会自动回滚 profile 文件，面板显示错误码与日志尾部；同一时间只允许一个安装任务。
